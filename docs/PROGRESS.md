### 2. 单位系统 —— A2「单位本位」模型 ⭐（决策）
用户自建食材时可从 ~35 个单位里选一个（个/块/瓣/杯…），**按该单位填营养、按该单位计量**，不强转克。
- **落地**：Ingredient 加 `nutrition_basis_amount` + `nutrition_basis_unit` 两列；营养 = 每基准值 × 数量 / 基准量；规范单位 = `nutrition_basis_unit`。食材库/USDA 仍是克本位 `(100,'g')`，用户单位本位是 `(1,'块')`。
- **`allowed_units`** 计算属性：库存/菜谱里该食材只能选这个单位（除非当初选的就是克/ml）。`resolve_quantity()`（原 `resolve_grams`）按此换算。
- **trade-off（简历素材）**：选 A2 而非 A1（全量 quantity_grams 重命名）——在**保持营养诚实**（用户单位的营养不被伪造成克）的前提下，把改动面和回归风险降到最小。104 个后端测试全绿 + 迁移在全新库验证。

### 3. 选食材界面改 tab
加库存的选食材步骤分「全部食物 / 我的食物」两 tab + 排序（最近添加 / 字母）+ 营养预览 + **常驻"创建新食物"按钮**（不必先搜不到才创建）。后端 `list_ingredients` 加 `sort` / `scope` 参数。

### 4. 国际化 i18n —— 双语 EN/中 可切换 ⭐（决策）
**方案 C（双语可切换），默认英文。**
- **架构**：react-i18next + `en.json`/`zh.json`，key-based；语言存 `localStorage(mf_lang)`；新增账户页（Account）放语言切换开关。
- **单位标签**：value（规范单位，多为中文如"块"）**存进数据库不动**，只在 `units.js` 用英文标签表按语言显示（个/只/颗/枚 → piece）。斤/两保留罗马音。
- **日期**：`dateRange.js` 的 `weekdayLabel`/`fullDate` 改 `toLocaleDateString(locale)`，全局跟随语言。
- **翻译边界（trade-off / 简历素材）**：UI 文案 key-based 翻译 + localStorage 持久化；**明确区分"UI 文案 vs 用户/AI 生成数据"**——用户自建食材名、AI 菜谱正文保留创建语言，规避数据层双语化的成本与翻译准确性风险。

### 9. A5 删除时退回库存 + A6 零数量批次隐藏（决策，见 DECISIONS I15）
- **删除已完成的餐次**：弹窗三选一「取消 / 只删记录 / 删除并退回库存」（餐计划页、今日概览共用 `useEntryDelete`）；未完成的照旧普通确认。
- **删除计划**：先查计划里有几顿已完成，有则统一问一次是否全部退回。
- **退不回去的部分**（原批次已被手动删）：跳过，记一条 `reversal_lost` 冲销流水让净额归零（反复撤销不会重复提示），并在操作后提示用户。撤销完成同样提示。
- **A6**：用到 0 的批次保留在数据库（退回原批次要用，保留过期日 / 储存区），`GET /inventory` 默认不返回，`?include_empty=true` 可查看。首页临期提醒也不再出现 0 数量批次。
- **接口变化**：删除餐次 / 计划 204 → 200，返回 `{unrestorable}`；撤销完成返回 `{entry, unrestorable}`。
- **顺带修**：新建计划名为空时的提示缺翻译 key（`mealPlans.errPlanName`）。
- **简历素材**：退回必须在删除之前、同一事务内完成（删后流水的 `source_entry_id` 被置空就找不到了）；退不回去的也记冲销流水，保证净额回补幂等。+10 测试（137 → 147）。

### 10. A4.2「今天」按用户时区 + A4.1 采购不算过期库存（决策，见 DECISIONS I16）
- **问题**：服务器按 UTC 取日期，纽约晚 8 点后已算成第二天 —— 当天到期的批次被当成过期、当天晚餐被当成「已过日期」不占预留。
- **做法**：前端 `api.js` 每个请求带 `X-Timezone`（浏览器 IANA 时区）；后端 `app/core/dates.py` 的 `get_today` 依赖按它算当地日期，缺失 / 无效一律退回 UTC、不报错。原先 8 处 `date.today()` 全部改走这个依赖（临期状态、预留、完成扣减、手选校验、采购预览 / 生成 / 重算 / 入库日期、AI 排餐起始日、Quick Log、默认计划）。
- **依赖**：新增 `tzdata` —— 新版 `python:3.12-slim` 不带系统时区数据，没有它线上会静默退回 UTC。`uv add` 只加这一个包（`uv.lock` +11 行，其他版本不动，吸取 Week 11 DEP0 的教训）。
- **A4.1**：采购缺口（I7）与预扣视图（I6）计算「现有库存」时排除过期批次（当天到期仍算），与库存预留（I14）口径一致 —— 库存页提示缺的，采购页也会让买。
- **验证**：CORS 预检带 `x-timezone` 在线上域名下通过；测试用 UTC+14 / UTC−11 两个时区证明日期由请求头决定。+10 测试（147 → 157）。
- **简历素材**：部署后才暴露的时区 bug —— 请求头带时区 + 服务端统一依赖、无效退回 UTC 不中断请求、用 `tzdata` 兜底精简镜像。

### 11. A8 采购去重 —— 在途量（决策，见 DECISIONS I17）
- **四个重复入口**：①多张清单同一缺口各出现一次 ②缺口页「加入清单」后缺口不变、可反复加 ③同清单同食材 auto + manual 两行 ④重算不扣手动加的量。
- **在途量** = 所有进行中清单里未购、买了要入库的量（按食材合计）。缺口先扣在途量才是「还需要加」：
  生成新清单 / 重算清单时 auto 只加差额；缺口预览多返回 `in_list_grams` / `to_add_grams`，已安排够的显示「已在清单中」。
- **加入清单**：同清单已有该食材未购 manual 行则并入（改量），不新建；auto 行不并（重算会删未购 auto，并进去的量会丢）。
- **显示**：同清单同食材 auto + manual 合成一行（标「自动 X + 手动 Y」），数据库仍多行；结算代表行时后端 `close_sibling_items` 一并标记已购，只入库一批。
- **顺带修**：采购页数量按食材规范单位显示；单位本位食材结算原先前端写死 `g` 会被 422 → 改传规范单位；食材名 / 单位由后端随条目返回（不再依赖 `/ingredients` 前 100 条）。
- **简历素材**：用库存 / 采购系统里的标准概念「在途量（on-order quantity）」一处解决三个入口的重复采购，同时保留 I8 的 auto / manual 双来源、不改表结构。+12 测试（157 → 169）。
